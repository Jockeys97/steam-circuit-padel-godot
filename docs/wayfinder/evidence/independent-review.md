## 3. What I could NOT check, and why

- **Anything audible.** `AudioServer.get_driver_name()` is `Dummy` on this host; no sound device exists. Claim 7 can only be checked as "the right `play_event()` was called with the right contract id", never as "it sounded right".
- **Rendered frames, screenshots, the windowed exported binary, and the editor-vs-export difference at runtime.** No GPU, software GL only, and rendering runs are out of scope for this review. H-1 is therefore reported from static code + pack archaeology (`pck-list.py` + `strings` on `padel.pck`), not from a screen.
- **Frame-rate behaviour by measurement.** H-2/H-3 are argued from the code and from `physics_ticks_per_second=120`; I did not run a windowed 60 Hz vs 144 Hz comparison, so the exact dropped-edge rate is unmeasured.
- **A human verdict on the playable slice** — feel, camera composition, legibility of the HUD on a real frame. No human ran it in this review.
- **Windows / macOS builds.** Only three Linux x86_64 presets exist; the platform set is an open product-scope question per the preset header.
- **Live Steam behaviour.** `Engine.has_singleton("Steam")` is false (asserted at `save_steam_test.gd:705-706`) and the addon is absent; every Steam assertion is against `MockSteamBackend`, which states on itself that it is a mock (`mock_steam_backend.gd:65-72`) and the factory never selects the real backend (`steam_backend_factory.gd:42-45`). That seam cannot be mistaken for a live Steam path — but nothing about Steam is verified.
- **Physical gamepad input.** No pad on this host; the input audits assert the `InputMap`/scheme layer, not a real device.
- **Whether Godot 4.7.2 actually honours `override.cfg` vs the preset option `application/main_scene`** for the boot scene of the exported desktop build. The evidence file claims it was measured (§5, "main scene forensics"); I did not re-run that windowed export. Note that `project.godot:10` still points `run/main_scene` at `res://tests/SmokeTest.tscn`, so the shipped boot scene depends entirely on `override.cfg` sitting next to the binary.
