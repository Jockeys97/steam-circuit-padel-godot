## What this contract is, and what it is not

It is:

- the reference's **688 keys** per locale in the port's `res://` tree, generated by JavaScript's own
  rules rather than approximated by a regex;
- the **108 message ids** the ported simulation can emit, derived from its source;
- the **resolution rules** that turn those ids into the reference's sentences, declared as data so
  both the port and the test read the same thing;
- a **drift test** that goes red when the port's data stops matching `js/i18n.js`, when the
  reference moves under the port, when a new emit site adds an id nobody has written down, and when
  the debt ledger stops being a true statement — plus eleven injected-drift controls proving it is
  not blind.

It is not:

- a Godot module I ran. `locale.gd` is written against the contract but **never executed by an
  engine** — see "Not done". The rules it implements are verified by the test's mirror resolver
  against the live reference module, not by Godot.
- a translation. There is no German table, and nothing here invents one (see below).
- a UI. Nothing calls `Locale.t()` yet: slice S4 wires it into the HUD and menus.

## 1. The authoritative extraction: 688 × 2 keys, and the 7 keys that exist twice

`t()` in the reference is `DICT[lang][key] ?? DICT.it[key] ?? key` (`js/i18n.js:1408-1414`) with
`let currentLang = "en"` (`js/i18n.js:1398`). The port's locale data is that dictionary.

The generator (`extract-i18n.mjs`) does **not** regex the values out. It brace-matches the
`const DICT = { … }` literal out of the file and evaluates it with `new Function("return (…);")()`,
so escapes, unicode and duplicate keys behave exactly as in the browser. It then asks the reference
module itself: for each of the 688 keys × 2 locales it calls `setLang(lang); t(key)` and requires the
value to equal the extracted one — **1 382 runtime comparisons, 0 findings** — plus the fallback
chain, the unknown-key rule and the unknown-locale rule.

That matters here, because `js/i18n.js` writes seven keys **twice per locale** and a JavaScript
object literal keeps the last value in the first position:

| key | written (it) | effective value |
|---|---|---|
| `shotPerfect` | `PERFETTO`, `PERFETTO` | `PERFETTO` |
| `shotGood` | `BUONO`, `BUONO` | `BUONO` |
| `shotEarly` | `IN ANTICIPO`, `ANTICIPATO` | **`ANTICIPATO`** |
| `shotLate` | `IN RITARDO`, `RITARDATO` | **`RITARDATO`** |
| `shotModeControl` / `Power` / `Balanced` | identical twice | unchanged |

`PLAN.md` slice S2 and the "Outcome" list quote *"PERFETTO / BUONO / IN ANTICIPO / IN RITARDO"* —
the superseded strings. A player sees `ANTICIPATO` / `RITARDATO`, because that is what the browser
build does. The generated file records the duplicates in `DUPLICATE_KEYS` and carries the effective
values, and the test fails if a key is written twice and the last-wins rule is not what the
evaluation produced.

Counts, from `node tools/i18n-port/extract-i18n.mjs` (exit 0):

```

```

The emitted file parses back to exactly the extracted tables (emitter ↔ parser round-trip asserted
on every generator run), and generation is **idempotent**: two consecutive `--write` runs produced
the same sha256 `5f16413e…a5cb2` (`cmp` exit 0). No timestamps, no hostnames, so a diff of the
generated file reads like a diff of the reference.

## 2. The message ids the ported simulation emits: 108 ids from 69 sites

The simulation stores ids where the reference stored rendered text (`godot/src/sim/state.gd`: the
`events` ring and `pointMessage`; `t()` is one of the four couplings stripped by
`simulation-port-boundary.md` §2). `emit-analysis.mjs` derives the id set from `godot/src/sim/*.gd`:

- **69 emit sites** — every `add_event(state, <expr>)` call and every `state.pointMessage … <expr>`
  assignment, found by balanced-paren scanning (not by regex on the line), with the enclosing
  function recorded;
- a site whose expression is a literal or a ternary of literals yields its ids directly; comparison
  operands (`winner == "player"`, `kind == "long"`) and dictionary indices
  (`assessment["quality"]`) are not ids and are dropped;
- **8 dynamic sites** (a `%` format or a bare variable) must be declared in
  `tools/i18n-port/emit-sites.json`, and each declared substitution is re-derived from the source it
  claims to come from and must match:
  the literals at the call sites of `serve_fault` / `score_point`, the id-shaped literals inside
  `report_shot_error`, the suffix set of the reference table's own `tactic_*` keys, and the length of
  the frozen `eventLines` list.

Result (`node tools/i18n-port/emit-analysis.mjs`, exit 0):

```
# emit sites: 69 (7 distinct dynamic site shapes, all declared)
# ids the port can emit: 108 — {"ok":98,"no-key":9,"no-params":1}
```

The critical property: **an undeclared dynamic site is a hard failure**, so `add_event(state, "%s" % x)`
cannot reach the screen without someone writing down what it can produce. Same for a new literal id
that is not in the table.

Three causes, all in `godot/src/sim/**`, which this task may not write:

- **rc1 — ids built by concatenation.** `sim.gd:2034` composes `"%s secondServe" % reason` and
  `sim.gd:2038` composes `"doubleFault:%s" % reason.to_lower()`. Neither is a key, and the
  lowercase step destroys the id it started from. The reference renders at emit time instead:
  `` `${reason} ${t("secondServeSuffix")}` `` (`js/game.js:2123`) and
  `t("doubleFault", { reason: reason.toLowerCase() })` (`js/game.js:2128`). The four
  `point*:doubleFault:*` ids inherit the failure through the `pointYou`/`pointOpp` composite rule.
- **rc2 — lost parameters.** `serveHint` is stored bare; its value is
  `"{ordinal} di servizio dal basso{suffix}: cerca il diagonale."` and the reference fills both
  placeholders at the call site (`js/game.js:2629-2632`). Resolved today it would print the braces.
- **rc3 — the reference's own untranslated literal.** `js/game.js:2135` hardcodes
  `state.pointMessage = "LET · Servizio da ripetere"` — no `t()` call, so that string is not
  translatable in the browser build either. Adding a key is a product decision for Luca (the port
  must not invent strings the reference does not have); the sentence *"Servizio da ripetere"* does
  exist inside the value of `evLet` if he wants to bind it.

## 3. The resolution rules — and what they produce

Composite ids are the port's encoding of a `t()` call the simulation may not make. They are declared
in `tools/i18n-port/resolve-rules.json` and bound per template, not guessed:

| rule | binding | reference |
|---|---|---|
| `controlMsg` | `placeholder` → `{position}` = `t(arg)` | `js/game.js:455-456` |
| `pointYou` | `suffix` → `t(parent) + " · " + t(arg)` | `js/game.js:2110` |
| `pointOpp` | `suffix` → same | `js/game.js:2110` |

Resolved with the port's tables (mirror resolver, engine-free):

| id | `it` | `en` |
|---|---|---|
| `ai_leggenda_name` | Leggenda del Circuito | Circuit Legend |
| `AI_LEGGENDA_NAME` | `AI_LEGGENDA_NAME` | `AI_LEGGENDA_NAME` |
| `controlMsg:roleBackPos` | Controlli il giocatore di fondo. | You control the player at the back. |
| `controlMsg:roleNetPos` | Controlli il giocatore a rete. | You control the player at the net. |
| `pointOpp:msgOut` | PUNTO AVVERSARIO · Palla fuori dal campo. | OPPONENT POINT · Ball out of the court. |
| `pointYou:evServeValid` | PUNTO TUO · Servizio valido: rimbalzo nel riquadro opposto. | YOUR POINT · Valid serve: bounce in the opposite box. |
| `tactic_staggered` | Tattica di coppia: disposizione sfalsata. | Pair tactic: staggered formation. |
| `eventLine3` | Volée fulminea sul circuito! | Lightning volley on the circuit! |
| `evChiquita` | Chiquita bassa sui piedi degli avversari! | Low chiquita at the opponents' feet! |
| `serveHint` | `{ordinal} di servizio dal basso{suffix}: cerca il diagonale.` | `{ordinal} serve from below{suffix}: aim for the diagonal.` |

The `AI_LEGGENDA_NAME` row is the point of the whole exercise: the reference's fallback returns the
id, silently, and that is what the player read for a whole match (git `1652240`). The port keeps the
semantics — `Locale.is_resolvable()` exists so a caller can assert instead — and the test asserts
both directions: the key exists in both locales (so the id never reaches the screen), and the
uppercase variant still comes back as itself (so the failure mode is named and reproducible, not
papered over).

**Every composite id the port emits that resolves is compared against the live module**: for each
one, and for both locales, the port's rule output must equal what `js/i18n.js`'s own `t()` produces
for the equivalent JavaScript expression — **32 comparisons, 0 mismatches** — on top of the 1 382
single-key comparisons the generator already makes.

## 4. Reference parity, reproduced on the port side

The browser build enforces string-table invariants in `scripts/i18n-audit.mjs`; the port has to hold
the same ones, so the drift test re-derives them from `js/data.js` and the port's own tables:

- key parity: no key exists in one locale and not the other (**0 asymmetries**, 688 = 688);
- placeholder parity per key: a translation that drops `{n}` prints half a sentence, one that
  invents a placeholder leaves braces on screen (**0 mismatches**);
- **78 runtime-composed keys** across five families — `athlete_{id}_{name,role,desc,special}` (24),
  `arena_{id}_{name,desc}` (18), `ai_{id}_name` (4), outfit `nameKey`s (26), `obj_{id}` (6) — all
  present in both locales. These are the keys nobody reads while writing them; they appear on screen
  in match, for one combination of data. `scripts/i18n-audit.mjs` independently reports the same
  figure on the browser side (`{"chiavi": 688, "usateEsplicitamente": 468, "composteVerificate": 78,
  "lingue": 2}`, exit 0), which is the corroboration this check was written to match.

## 5. Language: Italian and English, and German is *missing*, not invented

The reference has exactly two tables, `it` (`js/i18n.js:2`) and `en` (`js/i18n.js:699`). There is no
German table anywhere in `js/**`, `index.html` or `styles.css`. `setLang("de")` does not fail: it
sets `currentLang = "it"` (`js/i18n.js:1400-1402`) and every string comes out **Italian**, measured
against the live module for `de`, `fr`, `es`, `zz`.

So the honest statement is: *a German request is answered in Italian by the reference*, and the port
reproduces that. `resolve-rules.json` records it under `absentLocales` with the evidence, and the
drift test fails if `de` is not recorded as absent, or if it ever appears as a table without the
entry being deleted. Any German text has to be supplied by a human as a real third table; a machine
translation invented here would show a German player text the reference never had, and none of the
78 composed keys would have been verified against it.

## 7. Red control — the test is not blind

Eleven mutations are applied to **in-memory clones** of the sources (nothing on disk is touched) and
each must produce the expected failure; if any is not caught, the test itself fails. All eleven are
caught, and each scenario also self-checks that its mutation actually changed something, so a
scenario whose anchor moved cannot pass by doing nothing.

| scenario | injected drift | verdict |
|---|---|---|
| `port-string-changed` | a string in `locale_data.gd` edited by hand | RED |
| `port-key-removed` | a key removed from the port's data | RED |
| `reference-moved` | a string edited in `js/i18n.js` under the port | RED |
| `reference-moved-with-regen` | reference edited **and** the data regenerated, contract hash stale | RED |
| `new-emit-site-unknown-id` | `add_event(state, "evNonesuch")` added | RED |
| `case-typo-id` | an existing site's id typed `"EV_CHIQUITA"` (the `AI_LEGGENDA_NAME` class) | RED |
| `undeclared-dynamic-site` | `add_event(state, "ev%s" % kind)` added, undeclared | RED |
| `new-score-reason` | a new reason flows into `score_point` without updating the declaration | RED |
| `table-key-renamed` | a key the port composes at runtime renamed in the reference | RED |
| `ledger-shrunk` | the ledger drops an entry it still cannot resolve | RED |
| `ledger-padded` | the ledger gains an entry that resolves | RED |

## Not done

1. **`godot/src/locale/locale.gd` has never been executed.** This task may not launch Godot, so the
   resolver is verified only through the test's engine-free mirror of the same rules. The Godot-side
   proof (a headless test that calls `Locale.t()` and compares against a table exported here) is the
   natural next step and belongs in `godot/tests/**`, outside this task's allowlist.
2. **No UI consumes it yet.** S4 (HUD and main menu) has to call `Locale.t()`; nothing in
   `godot/game/**` exists in this working tree. Until then the contract is a promise, not on screen.
3. **The ten ledgered ids are still broken in the running game.** They need the three sim-side
   changes described in §2, which are outside this task's write allowlist. The ledger is the
