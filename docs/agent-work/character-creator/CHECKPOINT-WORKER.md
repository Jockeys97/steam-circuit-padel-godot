## 2. Art approach (implemented)

The frozen roster GLB is one mesh / one skin / one primitive / one baked material
(`docs/art/character-standard.md` §2), so it has no hair, skin or garment region and
can only be tinted whole. The custom athlete therefore gets **its own generated
modular geometry**, not a recolor of a baked body:

* `custom_character_kit.gd` emits a tapered segment per bone plus a sphere at each
  joint, grouped into material regions `skin | hair | outfit | accent | shoe`.
  Each region is its own surface with its own `StandardMaterial3D`, so skin, hair and
  garment colors move independently by construction.
* Vertices are weighted to the bones of a **skeleton it is handed** — the
  `mixamorig:` 28-joint rig the roster standard freezes (volpe's 24-joint fallback
  spelling is also resolved through the same role table, so the kit is
  naming-agnostic). Skin bind poses are the skeleton's own rest transforms.
* Variants are **different geometry**, not different colors: hair `buzz | crop |
  ponytail` (cap, cap+fringe, cap+strand), outfit `circuit | training | varsity`
  (sleeves/shorts, tank/leggings, one-piece with a shoulder yoke). Bounded palettes:
  6 skins, 6 hair colors, 6 outfit colors, fixed accent per outfit variant.

## 3. Runtime approach (implemented)

`custom_character_rig.gd` = an ordinary `AthleteRig` (skeleton + locomotion clips +
the four authored padel strokes + foot planter + pose layer) whose own baked mesh is
hidden (`mesh_instance.visible = false`) with the generated kit bound to that same
`Skeleton3D`. Consequences:

* **Animation compatibility comes for free**: the kit deforms on the same bones the
  existing clips drive; nothing is retargeted and no second rig exists.
* The base body is `maestro`, the roster athlete that follows the frozen 28-joint
  `mixamorig:` standard; its mesh is never rendered, so no baked atlas can leak in.
* Appearance is one small versioned record (`custom_character.gd`):
  `schema_version, display_name, skin_id, hair_id, hair_color_id, outfit_id,
  outfit_color_id`. Unknown/old ids normalize to documented defaults; the name is
  trimmed, whitespace-collapsed, upper-cased and length-bounded.
* Stats are **not** part of the record: `CustomCharacter.stats()` returns the frozen
  `rosterAverage` preset from `src/sim/frozen/data.json`, so every cosmetic choice is
  provably cosmetic.
* Persistence is its own file, `user://custom_character.json`, written temp + flush +
  close + rename (same discipline as `save_store.gd`), deliberately outside the
  profile save group so career/economy migration and a corrupt profile cannot touch
  it, and vice versa. Missing/corrupt/malformed reads answer the default record and
  report a reason; nothing throws.
