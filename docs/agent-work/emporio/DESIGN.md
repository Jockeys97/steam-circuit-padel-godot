# Emporio OST — approved implementation contract

## Scope and evidence
Godot3D only in steam-circuit-padel-11m / codex/integrate-arena-11m. Add credits, Emporio menu route, OST ownership and Jukebox access. Existing objectives stay unchanged; career.unlockAll is the LUCALE override. SoundtrackManager has the current OST catalog; inspect objective tables for exclusions before constructing shop inventory. Current Jukebox appears ungated: preserve old-profile access, do not revoke it.

## Product rules
- Currency: Crediti Circuito / Circuit Credits; no money, network, paid generation, boosts, or purchases of athletes/outfits in this phase.
- New profiles start at zero; menu/roster/training/victory OSTs are free starter tracks. Shop lists existing playable OST IDs other than starters and achievement-linked tracks, with ownership badges. Existing profiles grandfather all previously available non-objective OSTs exactly once. Never migrate the real user's profile during automated tests.
- Prices: 150 standard arena OST, 250 special/epic tracks. Use explicit existing catalog category mapping; no price derived from labels supplied by UI. Roughly a few completed short matches per OST, not dozens.
- Completed quick/tournament/career match reward: 20 completion + 2 per actually played point (both sides), capped at 80 variable credits, +15 for victory. No difficulty penalty; duration/format differences reflected by points actually played, not wall-clock or waiting. Exclude drills, aborted games, demos/probes/dry-run fixtures. Do not modify simulation state, RNG, balancing, golden reference captures, run.sh or project.godot.
- Award at the authoritative actual completion boundary, not mounting ResultScreen or querying result_payload. A unique non-simulation match ID and persisted receipt prevent double award across repeated finish, UI reopen, restart. Rematch generates a new ID. Show reward and balance on results.
- Purchase validates known eligible catalog ID, integer catalog price, ownership and funds centrally. Ownership and debit persist together atomically; failure changes neither, UI reports error. Same-item duplicate/reentrant purchases cannot double debit. Credits never negative. LUCALE gives access, not a fake huge balance, and never debits for unlocked content.

## Architecture and failure safety
Use one shared economy service and one atomic saved record for wallet, owned OST IDs, migration version and award receipts, through established SaveStore atomic semantics. Prefer a dedicated `economy` save group to avoid stale career/profile overwrites; update schema/group integration and cloud enumeration only as required. Refused future versions must remain refused, not overwritten. Preserve other five groups and unknown fields. Migration distinguishes genuine existing profile files from an empty/default new profile before defaults are written. Corrupt/refused economy must not trigger a fresh legacy grant. Service operations return structured success/reason/balance/owned/reward state.

Presentation: Emporio route in actual initial menu, Italian/English labels, balance, title/category/price/owned/insufficient states, confirmation before debit, Back, controller focus/confirm and right-stick scrolling through existing host. Jukebox lists locked tracks honestly and routes to shop; only owned content playable from Jukebox. Do not gate runtime match music or wire automatic OST gameplay in this phase. Preserve transport, covers and audio changes from concurrent tasks.
